# Negative control for Lean v4.35.0's `leanchecker` (2026-10-16)

`BadKernel.lean` adds the false theorem `NegControl.bad : False` with the proof `True.intro`, bypassing the kernel (`debug.skipKernelTC`). It compiles (`neg-compile.txt`), and `lake env leanchecker` rejects the module with "leanchecker found a problem … (kernel) declaration type mismatch" and exit code 1 (`neg-check.txt`). This shows that the exit code 0 of `leanchecker` on the proof modules is a real replay through the kernel. The file was compiled in a scratch location and removed from the project afterwards; it is not part of any proof. (For Lean v4.27.0, the gates and Comparator were tested on planted faults in `verification/lean-checks/A352275/outputs/negative-controls.txt`, and nanoda was shown to reject a tampered proof there.)
